# launch-checklist

Предзапусковая проверка сайта целиком: маршрутизация, индексация, шеринг, производительность, аналитика, юридические страницы. Безопасность — отдельным блоком через скилл **security-audit** (в этом же репозитории). Этот скилл его не дублирует.

## Принципы
1. **Проверять запуском.** Многие ошибки не видны в коде: 404 со статусом 200, `noindex`, уехавший со стейджинга, sitemap со ссылками на localhost, og:image за авторизацией. Проверяй **прод-сборку** (`npm run build && npm run start`): dev-режим отдаёт другие статусы, заголовки и метаданные.
2. **Только свои сайты.** Скрипт делает только GET-запросы (не больше 30). Для localhost подтверждение не нужно; внешний домен — только свой, скрипт спросит.
3. **Статус пункта — по наблюдению:** ✅ в порядке / 🔴🟡🔵 проблема / неприменимо (с причиной) / не проверено (с причиной).
4. **Код не менять без подтверждения.** Сначала список проблем с готовыми исправлениями, потом правки после «да».

## Порядок работы
1. **Контекст — одним взглядом на проект:** стек (Next.js App/Pages, SPA, другое), тип сайта (лендинг, портфолио, маркетплейс, блог), языки, аудитория (Украина, ЕС/Германия — от этого зависит юридический блок), есть ли кабинет и админка.
2. **Скрипт** по прод-сборке:
   ```bash
   python3 <папка-скилла>/scripts/launchcheck.py http://localhost:3000
   ```
   На Windows — `python` или `py`. После деплоя повтори на своём домене: там проверятся HTTPS, www и заголовки хостинга.
3. **Чек-лист** — `references/checklist.md`, 8 разделов. Пройди пункты, которые скрипт не видит (стратегия рендеринга, noindex на служебных страницах, hreflang на всех версиях, CWV, право). Для Next.js готовые решения — в `references/nextjs.md`.
4. **Безопасность.** Если установлен скилл security-audit (обычно `~/.claude/skills/security-audit`), выполни его **быструю проверку**. Если нет — пройди раздел 5 чек-листа.
5. **Ответ:**
   - строка итога (🔴 / 🟡 / 🔵 / ✅);
   - таблица по разделам со статусами;
   - топ-5 «чинить до запуска» с готовым кодом;
   - что проверить руками после деплоя (раздел 8 чек-листа).

   В Claude Code сохрани отчёт в `LAUNCH_REPORT.md`. В чате отвечай в сообщении.

## Что считать блокером запуска
- главная или весь сайт закрыты `noindex` / `Disallow: /`;
- нет HTTPS или редиректа на него;
- мягкий 404 (несуществующие URL отдают 200);
- canonical или sitemap указывают на localhost или стейджинг;
- критичные находки security-audit (ключи в коде, открытые данные, AI-эндпоинт без авторизации);
- для коммерческого сайта в Германии — нет Impressum и Datenschutzerklärung; трекеры грузятся до согласия.

Остальное — улучшения по приоритету.

## Скрипт launchcheck.py
Проверяет:
- главную: статус, title, description, canonical, lang, viewport;
- HTTP→HTTPS и www↔без-www (на домене);
- честный 404 и утечку стека на странице ошибки;
- robots.txt: не закрыт ли сайт, CSS/JS, строка Sitemap, служебные пути;
- sitemap.xml: хост, https, выборочно до 4 страниц — статус, noindex, canonical;
- дубли по слешу на конце;
- hreflang, JSON-LD, Open Graph (и открывается ли og:image), twitter:card, favicon, apple-touch-icon, manifest;
- вес HTML, картинки без размеров, блокирующие скрипты, Google Fonts;
- трекеры без механизма согласия, Яндекс.Метрику;
- ссылки на политику, Impressum и условия.

На localhost абсолютные ссылки на прод-домен (из canonical, sitemap, og:image) переводятся на локальный адрес — прод не трогается.

Не видит: реальные Core Web Vitals, отрисовку JS-контента поисковиком, содержание юридических текстов, всё за авторизацией.

## Неточности в популярных чек-листах, которые стоит поправить
- **«Закрыть админку в robots.txt» — не защита.** robots.txt публичный и подсказывает атакующему пути. Служебные страницы закрывают авторизацией, от индексации — `noindex`.
- **`Disallow` и `noindex` на одной странице конфликтуют.** Если страница закрыта в robots.txt, поисковик не увидит её `noindex` и может проиндексировать URL по внешним ссылкам. Для `noindex` страница должна быть доступна для обхода.
- **Next.js `permanent: true` отдаёт 308, а не 301.** Для Google это равноценно, менять не нужно.
- **Яндекс.Вебмастер** — только если аудитория его использует. В Украине сервисы Яндекса заблокированы. Для Украины и ЕС: Google Search Console + Bing Webmaster Tools.
- **X-Frame-Options** устарел: современная замена — `frame-ancestors` в CSP (можно держать оба).
- **Google Analytics в ЕС** — только после согласия пользователя. Google Fonts с серверов Google в ЕС — риск по DSGVO (решение суда Мюнхена 2022): раздавай шрифты со своего домена.
