## 1. Сервер и маршрутизация
- [ ] **HTTPS + постоянный редирект** с HTTP (301/308) `[скрипт, на домене]`. HSTS — в блоке безопасности.
- [ ] **Один хост:** `www` → без `www` (или наоборот) постоянным редиректом `[скрипт, на домене]`.
- [ ] **Слеш на конце** — одна форма, вторая редиректит (Next.js: `trailingSlash`) `[скрипт]`.
- [ ] **Честный 404** на несуществующие URL, а не 200 и не редирект на главную `[скрипт]`. В Next.js App Router `notFound()`, вызванный после начала стриминга (глубоко под `Suspense`), отдаёт 200 + `noindex`. Проверяй статус curl'ом.
- [ ] **Страница 500** своя, без stack trace и деталей (`error.tsx`, `global-error.tsx`) `[скрипт — утечку стека на 404]`.
- [ ] **301/308-редиректы** со старых URL при переезде или смене структуры. Карта «старый → новый», без цепочек (A→B→C) и петель.
- [ ] **Стратегия рендеринга** по страницам: SSG/ISR для контента, SSR для персонализированного, CSR только за авторизацией. Главное: текст, который должен индексироваться, есть в HTML **без JS** — `curl -s URL | grep "ключевая фраза"`.
- [ ] **Превью и стейджинг не индексируются:** `X-Robots-Tag: noindex` или пароль; их canonical не указывает сам на себя как на основной сайт.

## 2. Индексация и SEO
- [ ] **robots.txt:** публичное разрешено, CSS/JS не закрыты, есть `Sitemap:`, на проде нет `Disallow: /` `[скрипт]`.
  - Служебные пути в robots.txt перечислять не нужно — это подсказка атакующему. Их закрывают `noindex` и авторизацией.
  - `Disallow` мешает поисковику увидеть `noindex` на странице. Выбирай одно: для скрытия из выдачи — `noindex` при открытом обходе.
- [ ] **sitemap.xml:** генерируется из данных, только канонические индексируемые страницы со статусом 200, абсолютные URL боевого домена, честный `lastmod` (или без него) `[скрипт]`. Больше 50 000 URL — индекс карт.
- [ ] **Canonical:** абсолютный self-canonical на каждой индексируемой странице; для URL с параметрами (`?utm=`, сортировки, фильтры) — на чистый URL `[скрипт]`.
- [ ] **Title и description** уникальные для каждой страницы: title ≈ до 60 символов, description ≈ 120–160, по сути страницы `[скрипт — главная и выборка]`.
- [ ] **noindex на служебных страницах:** вход, регистрация, кабинет, корзина, чекаут, внутренний поиск, страницы с фильтрами-мусором. Админка — за авторизацией (и `noindex`).
- [ ] **`<html lang>`** и **viewport** `[скрипт]`.
- [ ] **Hreflang** для мультиязычных сайтов: на каждой версии — ссылки на все версии, включая саму себя, плюс `x-default`, абсолютные URL, взаимность (если A ссылается на B, то и B на A) `[скрипт — главная]`. Язык в URL (`/uk/`, `/de/`), а не только в cookie.
- [ ] **Чистые URL** (ЧПУ): латиница или единая транслитерация, дефисы, нижний регистр, без ID-мусора там, где можно.
- [ ] **JSON-LD** по смыслу: `Organization` + `WebSite` (главная), `BreadcrumbList`, `Article`, `Product`, для услуг — `LocalBusiness`/`Service`, `FAQPage` только для настоящих FAQ `[скрипт — наличие и валидность JSON]`. Проверка — Rich Results Test. Рейтинги (`AggregateRating`) — только из реальных отзывов на странице. Пользовательский текст в JSON-LD экранируй (`<` → `\u003c`).
- [ ] **Контент и ссылки:** один `<h1>` по смыслу, внутренние ссылки на важные страницы, `alt` у значимых картинок.

## 4. Производительность и Core Web Vitals
- [ ] **Пороги (75-й перцентиль реальных пользователей):** LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1. Реальные данные — PageSpeed Insights (блок полевых данных) и Search Console; локально — Lighthouse на прод-сборке.
- [ ] **Картинки:** `next/image` (WebP/AVIF, нужный размер), `width`/`height` или `fill` в контейнере с размером (против CLS), `preload` у LCP-картинки первого экрана (в Next ≤ 15 — `priority`), остальные — lazy `[скрипт — размеры и форматы]`.
- [ ] **Шрифты:** `next/font` (самостоятельный хостинг, `display: swap`, `subsets: ['latin', 'cyrillic']` для украинского), не больше 2–3 начертаний `[скрипт — Google Fonts напрямую]`.
- [ ] **JS:** размер бандла (`@next/bundle-analyzer`), тяжёлые компоненты (карты, редакторы, графики) — через `dynamic()`, сторонние скрипты — `next/script` со `strategy="lazyOnload"`. Tree-shaking и минификацию Next делает сам; проверять нужно результат, а не настройки.
- [ ] **Кэширование:** статика `/_next/static` — `immutable` (Next ставит сам; не перебивай в хостинге). HTML — по стратегии рендеринга.
- [ ] **Сжатие** (brotli/gzip) — обычно делает хостинг; проверь `curl -sI -H "Accept-Encoding: br" URL | grep -i content-encoding`.

## 5. Безопасность
Полная проверка — скилл **security-audit**: быстрая проверка перед запуском, полный аудит для проектов с деньгами и персданными. Минимум, если скилла нет:
- [ ] Секретные ключи только на сервере: ни одного секрета с `NEXT_PUBLIC_`/`VITE_`, `.env*` в `.gitignore`, в истории git ключей нет.
- [ ] Заголовки: CSP (в браузере блокирует инлайновый обработчик), HSTS, `nosniff`, `Referrer-Policy`, `frame-ancestors` (замена `X-Frame-Options`), `Permissions-Policy`.
- [ ] Формы: серверная валидация, rate limit по надёжному ключу, капча/Turnstile или honeypot. CSRF: server actions Next.js проверяют Origin сами; для своих API с cookie-сессией — проверка Origin и `SameSite=Lax`.
- [ ] Служебные страницы закрыты **авторизацией**, а не только `noindex`/robots.txt.
- [ ] Страницы ошибок и ответы API без stack trace.
- [ ] RLS на каждой таблице (Supabase), AI-эндпоинты за авторизацией и лимитом.

- [ ] **Аналитика:** GA4/GTM или без cookies (Plausible, Umami). Цели и события: заявка, регистрация, оплата `[скрипт — наличие]`.

- [ ] **Аптайм:** внешний монитор главной и ключевого API (UptimeRobot, Better Stack) с оповещением в почту/Telegram.
- [ ] **Логи** хостинга и функций: владелец знает, где смотреть; ошибки и отклонённые запросы видны.
- [ ] Search Console: подтверждён домен (DNS-запись), включены оповещения.

## 7. Юридические требования
Это ориентиры, а не юридическая консультация. Для коммерческих проектов тексты стоит сверить с юристом или генератором (например, eRecht24 для Германии).

**ЕС / Германия:**
- [ ] **Impressum** для коммерческого сайта (§ 5 DDG): имя/фирма, адрес, контакт, при наличии — регистрационные и налоговые данные; ссылка с каждой страницы, не глубже двух кликов `[скрипт — ссылка]`.
- [ ] **Datenschutzerklärung** (DSGVO): какие данные, цели, правовые основания, обработчики (хостинг, почта, аналитика, платежи), сроки, права пользователя `[скрипт — ссылка]`.
- [ ] **Согласие на cookies/трекеры** до их загрузки (TDDDG § 25); отказ так же прост, как согласие.
- [ ] **Сторонние встраивания** (Google Fonts, YouTube, Google Maps) — локально или «загрузить по клику» с согласием; YouTube — `youtube-nocookie.com`.
- [ ] **Договоры обработки (AVV/DPA)** с сервисами, которые обрабатывают персданные: хостинг, почта, CRM, аналитика.
- [ ] Для продажи услуг потребителям онлайн — AGB и информация о праве отказа (Widerrufsbelehrung).

**Украина:**
- [ ] Политика конфиденциальности и согласие на обработку персональных данных (Закон «Про захист персональних даних») для форм и регистрации.
- [ ] Для маркетплейса и платных услуг — публичная оферта / правила пользования.
- [ ] Если сайт ориентирован и на ЕС — применяются требования DSGVO.
