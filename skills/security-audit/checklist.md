# Чек-лист перед деплоем

То, что сканер не видит или видит только частично. Пройти вместе с пользователем, ответ по каждому пункту: да / нет / неприменимо.

## Данные и доступ
- [ ] У каждой таблицы Supabase включён RLS, есть политики на select/insert/update/delete (Dashboard → Advisors → Security).
- [ ] Пользователь A не может прочитать или изменить данные пользователя B — **проверено двумя аккаунтами**.
- [ ] Админские маршруты и server actions проверяют роль на сервере, а не только прячут кнопки.
- [ ] Служебные страницы закрыты авторизацией, а не только `noindex`/robots.txt; robots.txt не перечисляет пути админки (это подсказка атакующему).
- [ ] В обновлениях профиля и заказа нельзя прислать `role`, `price`, `user_id`, `status`, `balance`.
- [ ] Цена, сумма и статус оплаты определяются сервером; «оплачено» ставит только проверенный вебхук.

## Ключи и секреты
- [ ] Все ключи в переменных окружения; `.env*` в `.gitignore`; в истории git ключей нет (сканер проверил).
- [ ] Ни одного серверного ключа с `NEXT_PUBLIC_`/`VITE_`; service_role — только на сервере.
- [ ] На хостинге боевые ключи только в Production, превью — на тестовых.
- [ ] На всех платных API (OpenAI, Anthropic, Stripe, SMS, почта) выставлены лимиты расходов и алерты в консоли провайдера.

## Формы и боты
- [ ] Rate limit на логине, регистрации, сбросе пароля, OTP, формах и AI-эндпоинтах; **проверено подменой X-Forwarded-For** — лимит не сбрасывается.
- [ ] Капча или honeypot на публичных формах.
- [ ] Письма не уходят на адрес из формы без капчи и лимита; ввод в письмах и уведомлениях экранирован.
- [ ] Серверная валидация (zod и т.п.) с лимитами длины на каждой точке ввода.

## Вывод и заголовки
- [ ] Маркер `<b>audit-marker</b>` выводится текстом везде: страница, админка, письмо, Telegram, экспорт.
- [ ] CSP есть и **в браузере** блокирует инлайновый обработчик (`dynamic-testing.md`, раздел 2).
- [ ] HTTPS с редиректом, HSTS, nosniff, Referrer-Policy, frame-ancestors; сессионные cookies — HttpOnly, Secure, SameSite.
- [ ] Ответы API и страницы 404/500 не содержат stack trace и текстов ошибок БД (проверено на прод-сборке).
- [ ] Source maps не публичные; `.env`, `.git`, дампы не отдаются (livecheck по своему домену).

## Не развалится молча
- [ ] Тесты на ключевые защиты, которые падают, если защиту убрать.
- [ ] CI на каждый PR: линтер, типы, тесты, `npm audit`, сканер; ветка main защищена обязательными проверками.
- [ ] Хостинг-сборка не единственное место проверок (она тесты не запускает).
- [ ] Dependabot включён **вместе с графом зависимостей**; lock-файл в репо.
- [ ] Логи пишут отклонённые запросы (429/400/403, неверные подписи) без паролей и токенов, и владелец знает, где их смотреть.
- [ ] В CLAUDE.md / AGENTS.md записано, какие данные доверенные и почему.
- [ ] Бэкапы БД включены, восстановление хотя бы раз проверено.
