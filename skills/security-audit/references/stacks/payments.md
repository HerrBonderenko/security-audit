# Платежи, escrow, выплаты

## Главное правило
Сумма, статус оплаты и получатель выплаты определяются **только сервером** на основе данных из БД и проверенных событий платёжной системы. Клиент может сообщить только намерение: «хочу купить товар X».

## Вебхуки
- Подпись проверяется по **сырому** телу: Stripe — `stripe.webhooks.constructEvent(await req.text(), sig, whsec)`. Если сначала вызвать `req.json()`, проверка сломается.
- Идемпотентность: сохраняй `event.id` с уникальным индексом; повторная доставка того же события — no-op. Платёжки ретраят вебхуки, это штатное поведение.
- Порядок событий не гарантирован: не полагайся на то, что `created` придёт раньше `succeeded`.
- Статус «оплачено» ставит только вебхук (или серверный запрос к API провайдера), а не редирект на `/success?paid=true`.
- Сумму из события сверяй с суммой заказа в БД.

## Гонки (race conditions)
Классика: два параллельных запроса «вывести деньги» оба видят баланс 100 и оба проходят.
- Атомарная смена статуса: `update payouts set status = 'processing' where id = $1 and status = 'pending' returning *` — если вернулось 0 строк, запрос уже кто-то обработал.
- Баланс: `update wallets set balance = balance - $1 where user_id = $2 and balance >= $1` в одной транзакции с записью в журнал.
- Уникальные ограничения на «один раз»: промокод на пользователя, отзыв на заказ, выплата на сделку.
- В Supabase: такие операции — в `security definer` функции (с `search_path` и проверкой `auth.uid()`), а не последовательностью запросов с клиента.
- **Проверка запуском:** 10 параллельных одинаковых запросов (`for i in $(seq 1 10); do curl ... & done; wait`) — должен пройти ровно один.

## Escrow и статусы
- Опиши конечный автомат: какие переходы разрешены, кому (покупатель, исполнитель, админ, система).
- Каждый переход проверяет текущий статус в том же `update ... where status = …`.
- Деньги исполнителю — только из состояния «принято/подтверждено», с логом, кто и когда подтвердил.
- Отзывы и оценки пишет только участник сделки после её завершения, через сервер. Запись отзывов прямо с клиента — находка.

## Прочее
- Суммы — в минимальных единицах (копейки/центы) целыми числами, не float.
- Stripe Checkout / Payment Links: цена — из `price_id` на сервере, не из тела запроса.
- Возвраты и отмены — тоже через сервер и с проверкой роли.
- Логи платёжных операций — без номеров карт и полных реквизитов.
