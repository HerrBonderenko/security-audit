# Письма и уведомления

Письма и уведомления — «тихие» места. Бот отправляет форму, а вредоносный ввод срабатывает у владельца в почте, CRM или Telegram. Кроме того, форма, которая шлёт письма, — готовый инструмент спама от твоего домена.

## Open relay и спам от твоего имени
- **Адресат из запроса** (`to: body.email`) — сервис рассылает письма на любые адреса. Даже если это «подтверждение отправителю», бот вставит чужие адреса, и твой домен уйдёт в спам-листы.
  - Уведомления владельцу — на фиксированный адрес из конфига.
  - Письмо-подтверждение пользователю — только после капчи, с лимитом на адрес и на IP, без пользовательского текста в теле (или с жёстким экранированием и ограничением длины).
- **Заголовки из ввода:** `from` фиксирован, `replyTo` — только валидный email, в `subject` отрезаются `\r` и `\n`. Иначе возможна инъекция заголовков.
- SPF, DKIM, DMARC настроены для домена отправки (Resend/Zoho показывают статус) — это защищает от подделки писем от твоего имени снаружи.

## Экранирование в HTML-письмах
- Каждая подстановка пользовательских данных в HTML экранируется: `& < > " '`. Шаблон-строка с `${body.name}` без функции экранирования — находка.
- Шаблонизаторы с автоэкранированием (react-email, MJML с экранированием) — хорошо, но проверь места с «сырым» выводом.
- Ссылки в письмах из пользовательских данных — только `https://` и только на свои домены.
- **Проверка запуском:** маркер `<b>audit-marker</b> " ' &` → перехват письма (Mailpit/MailHog, тестовый режим провайдера, лог) → в HTML должно быть `&lt;b&gt;`.

## Telegram / Slack / Discord
- `parse_mode: 'HTML'` — экранируй `& < >` в пользовательских данных; `MarkdownV2` — экранируй `_ * [ ] ( ) ~ \` > # + - = | { } . !`. Иначе ввод подменяет разметку, вставляет ссылки, а сообщение может молча не доставиться («can't parse entities»).
- Токен бота — только на сервере. Вызов `api.telegram.org/bot<token>` из браузера отдаёт токен всем.
- Если бот принимает команды — проверяй `chat.id` отправителя по whitelist.

## Содержимое уведомлений
- Не отправляй в мессенджеры пароли, токены, полные персональные данные: история чатов хранится у третьей стороны.
- Уведомления о неудачных логинах, срабатываниях лимитов и неверных подписях вебхуков — полезный канал обнаружения атак (раздел 13 чек-листа).
